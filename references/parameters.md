# extract_keyframes 参数与原理

需要调参、或想知道"为什么抽出来的是这些帧"时读本文。日常使用只看 `SKILL.md` 的固定命令模板即可。

## 全部参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `inputs` | — | 输入文件（视频 / GIF），可多个 |
| `-o, --output` | 见下 | 输出位置。带 `--sheet-only` 时默认视频同目录，否则是 `<文件名>_keyframes/`；多个输入时 `-o` 失效 |
| `--sheet-only` | 关 | **只输出总览图**，不留单帧图片和 json（帧文件走临时目录，拼完即删） |
| `--sheet-width` | `9600` | 总览图目标宽度。**给模型读时务必降到 1600~2400** |
| `--cell-width` | `0` | 直接指定每格宽度（px），0 = 按 `--sheet-width` 反算 |
| `--sheet-quality` | `95` | 总览图 JPEG 质量（始终 4:4:4 不抽样色度） |
| `--sheet-max-cells` | `32` | **每张图最多几格**，超了自动分到下一张（0 = 不限制）。给模型读时设 12 |
| `--sheet-max-sheets` | `4` | **最多生成几张图**；关键帧超过 `张数 × 每张上限` 时按时间均匀抽稀 |
| `--cols` | `0` | 总览图列数，默认自动取「整图最接近正方形」的网格（**给模型读时固定 3~4**） |
| `-t, --threshold` | `0`（自动） | 画面变化判定阈值 0~1，越大越严格。**一般不要改**，见下 |
| `--noise-k` | `4.0` | 自动阈值的灵敏度倍数，越小抽得越多 |
| `--min-time` | `0.30` | 相邻关键帧最小间隔（秒），防瞬间抖动炸出一堆帧 |
| `--motion-time` | `1.5` | 画面持续变化时强制抽帧的间隔（秒） |
| `--max-frames` | `500` | 最多保留多少关键帧；超了按候选帧顺序等距抽稀（当前不是时间分层） |
| `--max-width` | `0` | 单帧图片最大宽度，`0` = 保持原尺寸（拼图最清晰） |
| `--quality` | `92` | 单帧 JPEG 质量 |
| `--format` | `jpg` | 单帧格式，`jpg` / `png` |
| `--no-contact-sheet` | 关 | 不生成总览图（只存单帧） |
| `--subtitles` | 关 | **额外出「字幕条总览图」**：每帧底部字幕区裁出来竖直叠放，10 句一张，见下 |
| `--subtitle-band` | `0.16` | 字幕条每帧保留的底部比例（0.05~0.60）。字幕在画面中间时调到 0.3~0.5 |
| `--subtitle-cells` | `10` | 每张字幕条图叠几行 |
| `--subtitle-max-sheets` | `4` | 最多几张字幕条图，超了按时间抽稀（4×10 ≈ 40 句字幕 ≈ 6k token） |
| `--subtitle-width` | `1600` | 字幕条图目标宽度（左侧标签栏按实测文字宽度自适应） |
| `--include-last` | 关 | 额外保留最后一帧 |
| `--json` | 关 | 只输出 JSON（每文件一行），含逐帧清单 |
| `--json-summary` | 关 | **只输出精简 JSON**（不含逐帧清单，帧多时省 2~4k token） |
| `-q, --quiet` | 关 | 不打印进度 |

也能当模块用：

```python
from extract_keyframes import extract_keyframes, summarize
meta = extract_keyframes("demo.mp4", sheet_only=True)
print(meta["width"], meta["height"], meta["duration"])   # 原尺寸 / 总时长（秒）
print(meta["overview"], meta["keyframes"][0]["time"])     # 总览图路径 / 第 1 帧时间戳
print(summarize(meta))                                    # 精简版：只留计数与图片路径
```

## 字幕条总览（`--subtitles`）

**为什么单独做这一层。** 字幕是"宽而扁"的信息：塞进 12 格网格里，每格在模型眼里只有
~380px 宽，40px 的字缩到 8px 全糊；于是 agent 只能去补读原尺寸单帧——**一张单帧 ≈ 1500 token**，
补 8 张就是 1.2 万，这是整条链路上唯一会失控的成本。

字幕条把每帧**底部 `--subtitle-band` 那一条裁出来**，竖直叠放，一行一句：
一张 1600px 宽的图装 10 行，每行仍有 ~1100px 宽、字完全可读，**token 和一张单帧一样（~1.5k）**。
成本直接降一个数量级，而且读到的是"逐句字幕"这种最高密度的文本。

- 左栏是 `#序号 时间戳`，宽度按最长的标签实测（不会压到字幕上），按字形实际高度垂直居中。
- 行高 = `底部比例 × 帧高 × (条宽/帧宽)`，所以竖屏素材也不会被拉变形。
- 分张与抽稀逻辑与总览图一致：先按 `cells × max_sheets` 抽稀，再按时间连续切。
- 输出 `subtitles.jpg` / `subtitles_01.jpg …`，JSON 里是 `subtitles` 列表 + `subtitle_count`；
  `--sheet-only` 时同理可用（帧在临时目录里现拼）。

**什么时候加**：总览图里字幕/小字读不清时**先加这个**，别急着读单帧。什么时候没用：
字幕不在底部（用 `--subtitle-band` 调大）、画面上根本没有字（那就读单帧看细节）。

## 静帧兜底（`insufficient_visual_change`）

抽帧的正确前提是"画面变化 = 信息"。**画面几乎不动的视频不满足这个前提**：
口播、访谈、讲座、一张图配旁白——全片只有开头一张和几个微动，抽出来 1~3 帧，
但输出照样是一段通顺的描述，**看起来完整、实际没内容**。这是本工具最危险的失败模式，
因为它不报错。

所以命中下面任一条件时，JSON 里带 `"insufficient_visual_change": true` +
`"visual_change_note"`，命令行也会打 `⚠`：

- 时长 ≥ `STATIC_MIN_DURATION`(60s) 且关键帧 < `STATIC_MIN_KEYFRAMES`(6)；
- 时长 ≥ `STATIC_SHORT_DURATION`(30s) 且关键帧 ≤ `STATIC_SHORT_KEYFRAMES`(2)。

调用方看到 `true` 应该**改走语音转写（ASR）**，而不是拿那一两帧编描述。

## `--json-summary` 与 `--json` 的区别

| | `--json` | `--json-summary` |
| --- | --- | --- |
| 逐帧清单（n / time / path / diff） | 含 | **不含** |
| 帧数多时的输出体量 | 100 帧 ≈ 3~4k token | ~0.9k 字符 ≈ 300 token |
| 用途 | 程序后处理、要逐帧时间戳 | **agent 读元数据决定怎么读图**（默认用这个） |

要看逐帧时间戳就读 `keyframes.json` 文件，别让它整段进上下文。
函数形式是 `summarize(meta)`，`extract_keyframes(...)` 的返回值不受影响（仍是完整 dict）。

## 临时目录兜底

`--sheet-only` 的中间帧本该落系统临时区，但沙箱 / 受限账户下 Windows 经常**建得出目录、
写不进文件**（`WinError 5 拒绝访问`）。脚本会先做一次真实写入探测，不可写就退到
输出目录下的 `.kf_frames_tmp`，拼完即删——不因为环境限制让 `--sheet-only` 直接失败。

## 阈值：为什么不要手动调

默认**自动**。原理：视频里大部分时间画面静止，所以"相邻帧差异"的中位数约等于**底噪**
（压缩噪点、轻微抖动）。阈值 = 底噪 × `--noise-k`，并夹在 `0.008 ~ 0.08` 之间。

- 完全静止的合成动画：底噪 ≈ 0 → 阈值 = 0.008（很敏感）
- 有噪点的实拍视频：底噪 ≈ 0.011 → 阈值 ≈ 0.043（不被噪点骗）

差异分数量级参考：

| 分数 | 含义 |
| --- | --- |
| `< 0.005` | 噪声 / 几乎没变 |
| `0.01 ~ 0.05` | 局部小变化（角落出字幕、小图标动） |
| `> 0.1` | 明显变化（整屏换色、转场、大幅运动） |

**抽得太少** → 调小（`--threshold 0.01` 或 `--noise-k 2`）。

**抽得太多** → **优先用 `--sheet-max-cells` / `--max-frames` 抽稀，不要调高阈值。**
抽稀是在已经选好的好帧里均匀挑，画面质量不受影响；而调高阈值有坑：阈值一高，
元素淡入淡出这类渐进动画就不再被当成"变化"，算法会在这类动画中途误判成"变化已结束"，
于是抽到元素还没出现 / 已经消失的**空白中间态**。

实测同一段 3 分钟讲解视频：

| 阈值 | 结果 |
| --- | --- |
| `0.008`（默认自动） | 134 帧，每帧都有完整内容 ✅ |
| `0.03` | 19 帧，一多半是空白画面 ❌ |
| `0.008` + 抽稀到 32 格 | 每格仍是完整画面，标题可读 ✅ |

## 选帧算法

1. 每帧缩成 200px 宽灰度小图，和上一帧求差异。
2. **两个角度同时看，取较大值**：
   - 全局平均差异 —— 整屏变化（转场、换色）
   - 8×8 分块中"变化最剧烈那一块"的差异 —— 局部小动作
     （只看全局平均的话，角落一个小物体移动会被大量没变的像素稀释掉，实测差异只有
     0.004、和噪声一个量级；看分块能拿到 0.06，区分度干净得多）
3. **选帧规则**：
   - 第一帧一定保留；
   - 画面变了不急着选，**等它变完**——变化结束后稳定下来的帧才是"完整展示"画面，选它；
   - 画面持续在变（运镜、长动效）就每 `--motion-time` 秒补一张，免得整段运动只出一张图；
   - 相邻关键帧至少隔 `--min-time` 秒；
   - 到片尾还在变就补上结尾画面；
   - 帧数极少的短 GIF（≤8 帧）全部保留。
4. **导出**：再完整解码一遍，命中帧号就存图。没用 ffmpeg 的
   `select='eq(n,0)+eq(n,17)+...'` 滤镜——关键帧上百个后那个表达式会超出 ffmpeg 解析器上限
   而直接报错，改成 Python 侧按帧号筛选，只解一遍。
5. **拼图**：网格排布，LANCZOS 重采样，存 JPEG 开 4:4:4，保证格子里文字不糊。

## 总览图构成

**只有三样东西，没有元数据条：**

1. **关键帧网格**：每格一帧，顺序 **左→右、上→下 = 时间顺序**。
2. **每格左上角的格号**：白色数字 + 黑描边，字号取格高的 15%，**烧在画面里**。
   跨全部总览图从 1 连续编号（`overview_02.jpg` 接着 `overview_01.jpg` 往下数）。
   压到长边 1568px 给模型看时仍然认得出——这是引用画面的定位方式。
3. **每格下方标签**：`#序号  时间戳`（秒），可直接和视频位置对应，与格号互为冗余。

尺寸 / 时长 / 帧率 / 总帧数 / 阈值这些**一律不印在图上**——它们对"看懂画面"没有帮助，
却会占掉一块图面高度、把每格挤小。这些数字都在 `keyframes.json` 里，需要时从那里读。

## 分张：清晰度的真正旋钮

读图工具会把每张图整体压到长边约 1568px 再交给模型。所以**每格能分到多少像素
只取决于「这张图里有多少格」**，跟图做多大基本无关——把图做大的唯一效果是更容易被拒收。

因此帧多时的正确做法是**多出几张图**，而不是往一张里塞满小格：

| 方式 | 每格在模型眼里 | 结果 |
| --- | --- | --- |
| 30 格塞 1 张（3 列 1600px） | ~380px 但整图 10 行、压完后 ~150px | 糊 |
| 30 格分 3 张、每张 10 格 | ~470px，压完后 ~380px | 小字可读 ✅ |

分配策略：先把帧均匀抽稀到 `sheet_max_sheets × min(sheet_max_cells, 16)` 以内，
再**尽量平均**地切成若干张（每张格数差 ≤ 1），保证每张清晰度一致、按时间顺序排列。
文件名：单张 `overview.jpg`，多张 `overview_01.jpg`、`overview_02.jpg` …
（`--sheet-only` 时是 `<视频名>_overview.jpg` / `_overview_01.jpg`）。

产出里 `overview` 是首张路径，`overviews` 是全部张的列表，`overview_count` 是张数。

## 性能

3 分钟 / 1920×1080 / 5386 帧：分析 + 原尺寸导出 + 拼 9597×6323 的图，约 22 秒。
本技能默认档位（1600px 小图 + 每张 12 格、自动分张）更快：实测 1 分 37 秒 / 1080p / 2910 帧，
抽 82 帧 + 4 张总览 + 6 张字幕条，**约 25 秒**。
多出几张图只影响读图次数，不影响抽帧与导出的耗时（帧只解码一遍）。
